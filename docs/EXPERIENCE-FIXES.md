# 快捷开关、音频时序与牌组交互修复

## 使用方式

可运行修复包：`dist/Anki-experience-final-26.8.1/Anki.exe`。关闭旧版窗口后启动这个文件。原 `dist/Anki-learning-workspace-26.8.1/` 程序保持原样。

左侧快捷栏新增滑杆图标，点击打开「快捷开关」。可切换复习工具栏、学习奖励弹窗、SoundCloud 歌单循环，以及原生四档／通过失败两档评分。再次点击入口、点击面板外或按 Esc 关闭。窗口移动或尺寸变化时关闭面板，重新打开时按当前窗口边界定位。面板过小时允许滚动。

复习工具栏隐藏后，整条容器及高度一起移除。快捷面板保留「恢复卡片布局」「结束复习 · 返回牌组」与评分模式入口；「工具 → 快捷开关（恢复复习工具栏）」也可打开面板，不依赖这条复习工具栏。工具栏状态使用当前账户的原生配置保存。

奖励弹窗共用 SynapsePro 原设置；评分模式共用 Pass/Fail 控制器及保存方法；歌单循环与音乐播放器内的同名复选框共用 `soundcloud_playlist_loop`。保存失败会提示原因并恢复原配置。AI 密钥、音乐歌单管理、番茄钟时长、布局参数、主题、快捷键映射及需要重启的模块启停仍保留在原设置页，避免快捷操作变成复杂配置页。

## 根因和修复

### 复习音频

原来 `_showQuestion()`／`_showAnswer()` 在发送渲染命令之前调用播放器，而网页渲染还要经过资源预加载、脚本及 MathJax 等异步步骤。因此声音可能先于卡片出现。

现在每次卡片或正反面切换生成新的音频版本，先停止旧队列。网页将当前内容设为可见并经过绘制帧后，返回对应版本的确认；Python 再验证卡片、正反面、实际页面可见性和版本，才启动该批音频。重复和过期确认不能再次播放。自动前进计时随可见确认开始，避免加载期间计时耗尽。没有提前选卡、提交学习记录或改变评分与调度规则；没有新增答案预取。

这里控制的是 Anki 的自动音频队列。卡片模板自己执行的任意 JavaScript 播放逻辑，不属于原生队列保证范围。媒体加载发生在卡片显示之后，不作为卡片显示的前置条件。

### SoundCloud

原来的 FINISH 监听仅更新停止状态，没有处理歌单末尾。现在使用官方 Widget API 的 `getSounds`、`getCurrentSoundIndex` 和 `skip(0)`，仅在多曲目列表最后一首结束且循环开启时回到第一首并播放。中间曲目沿用官方自动切歌；单曲链接不做单曲循环。关闭循环后不发出回到第一首的命令。

暂停、手动切歌、重新加载歌单及改变循环设置都会使尚未完成的末尾回调失效。列表、播放与暂停状态由官方事件更新，不把发送 `play()` 命令本身视为已经播放成功。

### 牌组三栏

原来的折叠调用整页 `stdHtml()`，重建目录、账户辅助组件和拖动处理器。现在直接更新该行的折叠状态和后代可见性，仍通过原生操作保存折叠设置；保存失败重新读取真实状态。

快速选择先合并短时间内的选择请求，并立即使旧渲染失效。牌组树未改变时，只更新三栏中的当前牌组名称、详情、计数和选中标记，保留目录、滚动和账户辅助组件。真正结构或数据变化仍走完整刷新。拖动辅助图形改为独立文本容器，避免复制表格行后列尺寸丢失和重复 DOM ID。层级修改仍由原生 `reparent_decks` 执行。

## 验证与边界

测试均使用 `runtime/` 下独立、关闭同步的合成账户，未打开或改写正式用户数据库。

- `just experience-test`：音频可见确认、过期回调、取消播放、保存失败回滚，以及已有评分键和布局回归；另含 7 项 SoundCloud 官方接口模拟场景。
- `just experience-smoke <新目录名> write` 与 `restart`：小目录、700 多个多层牌组、30 次快速选择、连续折叠、三栏内容一致性、窗口宽度 620／950／1400、自动音频、快速重绘、快捷面板操作、全屏和 80%／100%／150% 网页缩放、工具栏高度释放、层级与设置持久化。
- 已通过 39 项首次运行及 29 项重启检查，另含选择与折叠交错的过期回调回归。语音样本由 Windows 英文 TTS 生成；新卡顺序设置为原生随机顺序。实际鼠标拖动将父牌组移入另一父牌组，重启后多层结构和 12 张卡片保持完整。最终合成环境中 30 次快速选择合并后约 177ms 完成（单次测量，不是性能保证）。
- 真实 SoundCloud 测试能取得 12 首歌的列表。尝试原生控件点击、切至末尾和读取播放时长后，时长持续无效，播放未持续。因此在线「最后一首回第一首」和「关闭后末尾停止」尚未验收通过，不能用模拟测试代替。记录及截图保存在对应合成测试目录的 `soundcloud-live.json`／PNG。网络、曲目可用性、地区、登录或嵌入限制的具体原因尚未确定。
- `just check` 使用项目已有 [Windows 检查环境](local-startup-validation.md)，包含 UTF-8、Briefcase 缓存和本地作者白名单。裸环境的贡献者名册失败不通过修改上游名册处理。
- 最终全量检查通过：629 项 Rust、153 项 Python 库、171 项 Qt、78 项 TypeScript 测试，以及类型和格式检查。检查期间有 Qt／Sass 及音频线程退出告警，测试和检查命令退出状态成功。最终程序包再次通过 39 项首次运行、29 项重启检查；关键源码与包内文件 SHA-256 一致。证据位于 `runtime/experience-0912-package/` 和 `runtime/experience-delivery-*.log`。

缩放验证使用 Qt 窗口变化与网页 zoom factor，没有覆盖切换不同物理显示器的系统 DPI。此次性能结论来自合成数据，尚未对用户原有牌组和自定义卡片模板逐一复现。

## 数据与恢复

本次不迁移用户数据。关闭快捷开关可恢复原显示；复习工具栏也可从「工具」菜单恢复。新程序包与已有程序并存，保留原程序作为回退入口；不要用旧用户数据库覆盖之后产生的学习记录。测试数据库、语音样本、截图、日志和软件包沿用现有 Git 排除规则。
