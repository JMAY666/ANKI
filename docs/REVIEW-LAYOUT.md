# 复习卡片区域与底部操作栏

## 使用

- 拖动卡片左右边缘的短线调整宽度，卡片保持水平居中；拖动下边缘调整高度。改变的是原生卡片 WebView 的区域大小，字体缩放不变。
- 边缘显示横向／纵向调整指针及提示。边缘获得键盘焦点后，可用对应方向键微调，Home 恢复默认。
- 顶部「恢复布局」或双击任意调整边缘恢复占满可用区域。手动缩小高度后留下的空间属于用户选择的布局，恢复默认即可收回。
- 宽高按可用空间的比例保存在当前账户的本地配置 `reviewViewportLayout`，普通窗口和全屏共享该偏好。窗口缩小时临时限制到可用范围，不覆盖保存的偏好；卡片最小区域为 400 × 180 Qt 逻辑像素。
- 底部栏保留原有按钮、计数、间隔、计时和评分模式。普通尺寸下，合成卡片实测正面约 74、答案约 70 逻辑像素；具体高度随主题、字体和内容变化。窄窗时编辑／更多在评分按钮下方另起一行，栏高按必要内容增加。
- 返回牌组时隐藏调整边缘，恢复原来的页面宽高；下次进入复习继续使用已保存布局。

## 黑色留白的原因与处理范围

截图对应的一类模板使用 iframe 展示整张卡片，并仅在加载时用 `window.innerHeight - 5` 设置一次像素高度。窗口或全屏改变后，原生卡片区域已增大，iframe 仍保持旧高度，剩余部分显示深色背景。因此，大块黑色区域并不全属于底部按钮栏。

只读检查确认了上述尺寸设置方式。用不含个人内容的本地 iframe 重现了同类问题：修复前 iframe 保持 754 像素，而全屏卡片视口增长到 1260 像素；修复后另一轮窗口／全屏实测为 678／908 像素，iframe 同步为 673／903 像素，保留原来的 5 像素间距。

复习显示层只跟踪原本已铺满视口、在顶部且用内联像素高度定义的 iframe。它只更新运行中的元素高度，不更改 iframe 地址、不重载页面、不重新执行模板脚本。小尺寸嵌入内容、百分比／vh 等响应式高度和模板主动改写后的尺寸不由这个兼容逻辑接管。浏览／模板编辑预览未启用这项兼容逻辑。

底部栏另外移除了主题带来的过量上下内边距，并在切换正反面、评分模式或改变宽度时重新测量内容高度。原有自动隐藏设置仍然有效，新的测量不会把已经隐藏的栏强制打开。

没有修改已保存的卡片模板、笔记内容、媒体或复习调度逻辑。实际远程卡片服务未被测试脚本访问；iframe 尺寸、滚动、图片及交互保持使用本地合成内容验证。

## 验证与复现

所有构建和测试通过项目配方执行。隔离账户位于被 Git 忽略的 `runtime/`，不使用正式学习数据或同步账户：

```powershell
just build
just navigation-check
just builtin-test
just review-layout-smoke review-layout-test-001
just review-layout-smoke review-layout-test-001 restart
just check
```

`review-layout-smoke` 默认要求一个新的测试目录；`restart` 使用同一目录启动新进程。`diagnose` 模式只记录窗口、全屏、正面与答案面的 Qt 和网页尺寸，便于与旧软件包对比。设置 `ANKI_BUILTIN_PACKAGE_ROOT` 可让同一个测试运行最终软件包中的代码和资源；Windows 下的 `executable` 模式使用该软件包的 `Anki.exe` 启动既有合成账户，并等待诊断完成和正常退出。

界面验收覆盖真实鼠标拖动、最小尺寸、恢复默认、普通／全屏切换、正面／答案面、长文本和图片滚动、内嵌页面输入／展开／滚动状态保持、四档／两档评分切换、按钮点击、空格与数字评分键、深色主题、退出复习和新进程持久化。布局测试前后逐项比较合成集合中的 notes、cards、notetypes、templates 和 revlog；在实际评分操作开始之前确认这些记录均未改变。

补充回归覆盖无效布局配置、只恢复有效维度、拖动后的偏好保存、窗口缩小时不改写偏好、恢复默认、返回牌组、自动隐藏栏保持隐藏，以及旧式 iframe 的识别边界。
